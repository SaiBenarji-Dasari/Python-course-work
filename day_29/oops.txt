Core terms
User: The person (or another program) that uses the software.

Class: A blueprint/template for creating objects (e.g., class User).

Object: A real instance created from a class (e.g., user1 = User("alice")).

Encapsulation (enc) – e.g., Instagram
Simple definition: Bundling data and methods together in a class and restricting direct access to internal data.

Idea: “Keep data safe inside the object; expose only controlled ways to use it.”

Example (Instagram-like):

Class InstagramAccount has private fields like password, posts.

You can’t directly change password; you must call changePassword(old, new).

This protects your data and keeps rules consistent.

Inheritance (inh) – e.g., LinkedIn
Simple definition: A class (child) acquires properties and methods from another class (parent).

Idea: “Reuse and extend existing code.”

Example (LinkedIn-like):

Base class UserProfile with fields: name, headline, experience.

Child class LinkedInProfile inherits from UserProfile and adds connections, endorsements.

LinkedInProfile automatically gets name and headline without rewriting them.

Polymorphism (pol) – e.g., YouTube
Simple definition: Same method name behaving differently depending on the object type.

Idea: “One interface, many forms.”

Example (YouTube-like):

Base class Video with method play().

Subclasses: ShortVideo, LongVideo, LiveStream, each override play() differently (e.g., short loops, long has ads, live has chat).

Code can call video.play() without caring which type it is; the right behavior runs.

Abstraction (abs) – e.g., Phone
Simple definition: Showing only essential features and hiding complex internal details.

Idea: “Use the phone without knowing how the circuit works.”

Example (Phone):

You see buttons like call(), message(), camera().

You don’t see how signals are encoded, how the lens focuses, etc.

The phone class exposes simple methods; internal hardware/driver logic is hidden.

Quick mapping to your list
User → who uses the system.

Class → blueprint (e.g., InstagramAccount, UserProfile, Video, Phone).

Object → actual instance (e.g., myInsta, myLinkedIn, ytVideo1, myPhone).

enc (Instagram) → encapsulation: hide internal data, expose safe methods.

inh (LinkedIn) → inheritance: LinkedInProfile extends UserProfile.

pol (YouTube) → polymorphism: play() behaves differently for shorts, long videos, live.

abs (Phone) → abstraction: use call() without knowing radio/hardware details.
